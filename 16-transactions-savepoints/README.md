# 16. Транзакции, SAVEPOINT и процедуры

**Тема:** `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`, `ROLLBACK TO`, `COMMIT`/`ROLLBACK` внутри процедуры.
**Данные:** банковские переводы (`bank_demo`), корзина и чек (`products`, `baskets`, `cheque`, `sales`).

## Задание
- Задание 1: триггер, который при изменении количества товара в корзине синхронно меняет остаток и продажи.
- Задание 3: процедура оформления чека с проверкой остатков. Если товара не хватает, транзакция откатывается.
- Перевод денег между пользователями: одна транзакция с частичным откатом через `SAVEPOINT`.

## Файлы
- `bank_demo_schema.sql` — база `bank_demo`: пользователи и транзакции.
- `products_schema.sql` — таблицы `products`, `customers`, `cheque`, `sales`, `baskets` и тестовые данные для заданий 1 и 3.
- `transaction_examples.sql` — три примера: простой перевод, перевод с промежуточным `SELECT`, `SAVEPOINT` для отката части операций.
- `transfer_money_procedure.sql` — процедура перевода по имени пользователя одним вызовом.
- `tasks_1_3.sql` — задания 1 и 3: триггер синхронизации корзины и остатков, процедура оформления чека с проверкой остатков.

## Что в решении
- `BEGIN ... COMMIT` как граница транзакции для нескольких связанных операций.
- `SAVEPOINT` и `ROLLBACK TO` для отката одного действия без отмены всей транзакции.
- `COMMIT` и `ROLLBACK` внутри тела процедуры (PostgreSQL 11+). Процедуре это разрешено, функции — нет.

## Статус
Схема `products_schema.sql` восстановлена по прежним решениям: столбцы совпадают с кодом заданий 1 и 3. Файлы выполняются в порядке: схема, затем `tasks_1_3.sql`.

Пример 2 в `transaction_examples.sql` рассчитан на данные, где у Бориса достаточно средств: при меньшем балансе сработает `CHECK` на баланс.
