# 12. Хранимые процедуры

**Тема:** `CREATE OR REPLACE PROCEDURE`, `CALL`, `OUT`-параметры, `IF NOT FOUND`, `RAISE EXCEPTION`.

Процедуры, в отличие от функций, не возвращают значение через `RETURN`: они изменяют данные, а результат отдают через `OUT`-параметры.

## Задание
- Библиотека: выдача книги, возврат книги, проверка долгов читателя.
- Авторизация и регистрация пользователя по логину и паролю.
- Смена фамилии клиента с проверкой, найден ли клиент.

## Файлы
- `library_schema.sql` — база `library`: читатели, книги, выдачи.
- `procedures.sql` — `sp_issue_book`, `sp_return_book`, `sp_reader_debts`.
- `soso_schema.sql` — база `soso`, расширение `pgcrypto`, таблица `reg` и тестовые пользователи.
- `auth_registration.sql` — процедура `login_correct`: три ветки — регистрация нового логина, вход при верном пароле, фиксация ошибки при неверном.
- `clients_schema.sql` — таблица `clients` и тестовые данные.
- `change_last_name.sql` — процедура `change_last_name` и вызов с `OUT`-параметром.

## Что в решении
- `CREATE OR REPLACE PROCEDURE` с обычными `IN`-параметрами.
- `OUT`-параметр в двух вариантах: через `DO`-блок (значение нужно для дальнейшей обработки) и через `CALL` из psql (результат выводится клиенту).
- `IF NOT FOUND` и `IF/ELSIF/ELSE` для ветвления по результату `SELECT INTO`.
- Проверка бизнес-условий через `RAISE EXCEPTION` до изменения данных.
- Пароли в `auth_registration.sql` хранятся как хэш: `crypt(пароль, gen_salt('bf'))` из расширения `pgcrypto`. Сравнение делается через `crypt(введённый_пароль, хэш)`.

## Ключевые моменты
- `sp_return_book` ищет и обновляет только активную выдачу конкретного читателя и книги (`return_date IS NULL`).
- `sp_reader_debts` считает все займы читателя, по которым книга возвращена позже срока или ещё не возвращена, а срок уже прошёл.
