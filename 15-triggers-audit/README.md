# 15. Триггеры и аудит

**Тема:** триггеры `BEFORE` и `AFTER` на `INSERT`, `UPDATE`, `DELETE`; аудит через `OLD`, `NEW`, `TG_OP`, `TG_TABLE_NAME`; бизнес-правила через `RAISE EXCEPTION`; событийный триггер на `DROP`.

## Задание
Девять заданий (7.1–7.9) с триггерами:
- 7.1: срабатывание только при изменении определённых столбцов.
- 7.2–7.3: универсальный аудит изменений.
- 7.4: перехват вставки и замена её на `UPDATE`.
- 7.5–7.7: запрет операций, которые нарушают бизнес-правило (рейтинг товара, количество товаров в заказе).
- 7.8: событийный триггер, который перехватывает `DROP TABLE`.
- 7.9: логирование операций по дням недели(пятница, суббота).

## Файлы
- `triggers.sql` — все задания 7.1–7.9 одним файлом. Некоторые блоки используют таблицы и функции, объявленные раньше в этом же файле.

## Что в решении
- `AFTER UPDATE OF <столбцы>` срабатывает только при изменении этих полей (7.1).
- Универсальный аудит на `INSERT`/`UPDATE`/`DELETE` через `TG_OP` и `COALESCE(OLD, NEW)` (7.2, 7.3).
- `BEFORE INSERT` возвращает `NULL`, отменяя исходную вставку, и делает `UPDATE` вместо неё (7.4).
- `BEFORE INSERT` с `RAISE EXCEPTION` запрещает операцию (7.5–7.7).
- Событийный триггер на `ON sql_drop` (7.8).
- Логирование по дню недели через `EXTRACT(DOW ...)` (7.9).

## Особенности
- Функции разных блоков имеют разные имена: аудит — `t_7_2_audit_all`, проверка рейтинга — `t_7_5_rating_check`.
- Блок 7.8 использует расширение `dblink`. Оно должно быть установлено (`CREATE EXTENSION dblink`), а строка подключения настроена под вашу среду.
